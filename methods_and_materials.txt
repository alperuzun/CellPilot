METHODS AND MATERIALS

Overview

CellPilot represents a comprehensive, user-friendly desktop application specifically designed for end-to-end single-cell RNA-sequencing (scRNA-seq) data analysis. The platform integrates multiple computational modules within a unified graphical user interface, providing researchers with streamlined access to complex analytical workflows including quality control, preprocessing, dimensionality reduction, clustering, cell type annotation, cell-cell communication analysis, tumor prediction, and drug response evaluation. CellPilot addresses the growing need for accessible bioinformatics tools that can handle the complexity of modern single-cell genomics data while maintaining computational rigor and reproducibility.

Software Architecture and Implementation

Programming Languages and Framework Selection

CellPilot was developed using a multi-tier architecture combining modern web technologies with robust scientific computing frameworks. The frontend employs Electron 28.2.0 as the cross-platform desktop application framework, enabling native-like performance across Windows, macOS, and Linux operating systems. The user interface was built using React 18.2.0 with TypeScript 5.3.2 for enhanced type safety and maintainability. Material-UI 5.15.2 provides the component library, ensuring consistent and responsive design patterns throughout the application.

The backend infrastructure utilizes FastAPI 0.115.12, a modern Python web framework chosen for its automatic API documentation generation, built-in data validation through Pydantic models, and high-performance asynchronous request handling. This architecture enables real-time communication between the frontend interface and computational backend through RESTful API endpoints. The separation of concerns between presentation and computation layers ensures scalability and facilitates future development and maintenance.

Inter-Process Communication and Data Management

Communication between the Electron frontend and Python backend is facilitated through HTTP requests using the Axios library. The main Electron process manages system-level operations including file system access, dialog handling, and inter-process communication (IPC) between the main and renderer processes. Custom IPC handlers were implemented for secure file operations, particularly for loading input data files and custom marker gene uploads.

Data persistence follows a hybrid approach, with analysis parameters stored in JSON format for rapid access and large datasets handled through the HDF5-based AnnData format. This strategy optimizes both memory usage and I/O performance while maintaining data integrity throughout complex analytical workflows. Temporary files and intermediate results are systematically organized with timestamp-based naming conventions to prevent conflicts in multi-user environments.

User Interface Design and Interaction Patterns

The graphical user interface was designed following modern desktop application principles, featuring a tabbed layout that guides users through sequential analysis steps. The primary workflow tabs include: (1) Annotation for cell type identification, (2) Analysis for downstream computational modules, and (3) Documentation for comprehensive help resources. Each tab incorporates progressive disclosure principles, revealing advanced options only when needed to reduce cognitive load for novice users while maintaining full functionality for expert users.

Interactive elements include dynamic form validation, real-time parameter updates, and progress indicators for long-running computations. The interface automatically adjusts layout density based on screen resolution, ensuring usability across diverse hardware configurations. Error handling includes both inline validation feedback and comprehensive error reporting with actionable guidance for resolution.

Computational Environment and Dependency Management

Python Environment and Package Management

All computational analyses are performed within a carefully curated Python 3.9.7 environment managed through Conda, ensuring reproducible installations across different systems. The environment specification (environment.yml) precisely defines all dependencies with fixed version numbers to guarantee computational reproducibility. Key computational dependencies include NumPy 1.26.4 for numerical operations, SciPy 1.11.4 for statistical computations, and Pandas 2.2.3 for data manipulation and analysis.

The scientific computing stack is built upon established single-cell analysis frameworks: Scanpy 1.10.3 serves as the primary single-cell analysis toolkit, providing optimized implementations of standard preprocessing and analysis algorithms. OmicVerse 1.6.10 extends Scanpy functionality with additional visualization capabilities and streamlined workflows for complex analyses. AnnData 0.10.9 provides the core data structure, enabling efficient storage and manipulation of annotated high-dimensional matrices typical in single-cell datasets.

Specialized Analysis Libraries

Cell-cell communication analysis utilizes CellPhoneDB 5.0.1, implementing permutation-based statistical testing for ligand-receptor interaction prediction. The library has been integrated with custom visualization modules using ktplotspy 0.2.4 for generating publication-quality network diagrams and interaction heatmaps.

Copy number variation analysis employs inferCNVpy 0.4.5, which provides Python bindings for the inferCNV R package while maintaining compatibility with the broader Python scientific computing ecosystem. Drug response prediction integrates the CaDRReS-Sc framework through custom Python wrappers, enabling seamless access to pre-trained models and GDSC database integration.

Machine learning and deep learning components utilize PyTorch 2.2.2 with TorchVision 0.17.2 for drug response modeling, while scikit-learn 1.6.1 provides classical machine learning algorithms for clustering validation and dimensionality reduction techniques.

Single-Cell RNA-seq Data Processing Pipeline

Data Input and Format Support

CellPilot supports multiple input formats commonly used in single-cell genomics workflows. Primary support includes Cell Ranger output files (filtered_feature_bc_matrix.h5), 10x Genomics HDF5 format, and pre-processed AnnData objects (.h5ad). The system automatically detects file formats and applies appropriate parsing strategies, including sparse matrix handling for memory efficiency with large datasets.

Data validation includes verification of gene symbol formats, detection of species-specific nomenclature (human vs. mouse), and assessment of matrix dimensions for consistency checks. Users can specify whether input data represents raw counts or pre-processed expression values, with the pipeline automatically adjusting subsequent normalization steps accordingly.

Quality Control and Filtering

The quality control module implements comprehensive cell and gene filtering strategies based on established best practices in the single-cell genomics field. Cell-level filtering removes low-quality cells based on multiple criteria: (1) mitochondrial gene expression percentage (default threshold >5%, user-adjustable), (2) minimum gene detection per cell (default <250 genes), (3) minimum UMI counts per cell (default <500 counts), and (4) maximum gene detection for potential doublet removal (default >7000 genes).

Gene-level filtering removes genes expressed in fewer than 3 cells by default, reducing noise and computational burden. Additional filtering options include removal of ribosomal genes, immunoglobulin genes, and mitochondrial genes based on user preferences and experimental design considerations.

Doublet detection utilizes the Scrublet algorithm integrated through Scanpy, identifying potential cell multiplets based on artificial doublet generation and nearest-neighbor classification. The algorithm generates synthetic doublets by randomly combining transcriptomes from the dataset, then classifies real cells based on their similarity to these synthetic doublets.

Normalization and Transformation

Count normalization follows the standard approach of normalizing total counts per cell to 10,000 (CPM normalization), followed by natural logarithm transformation with pseudocount addition (log1p). This approach accounts for technical variation in sequencing depth while preserving biological signal for downstream analysis.

Alternative normalization methods are available for specialized use cases, including size factor normalization through the scran algorithm and SCTransform for variance stabilization. Users can select normalization strategies based on experimental design and downstream analysis requirements.

Feature Selection and Dimensionality Reduction

Highly variable gene (HVG) identification employs the Seurat v3 flavor implementation in Scanpy, which models the mean-variance relationship of gene expression and identifies genes with variance significantly higher than expected. The default selection identifies 2000 HVGs, with user-adjustable parameters for different dataset characteristics.

Principal Component Analysis (PCA) is performed on the scaled expression matrix of highly variable genes. The default configuration computes 50 principal components, with automatic determination of significant components using the elbow method or user-specified component numbers. PCA results are used for downstream neighbor graph construction and UMAP embedding.

Uniform Manifold Approximation and Projection (UMAP) provides non-linear dimensionality reduction for visualization, with parameters optimized for single-cell data: n_neighbors=15, min_dist=0.5, spread=1.0. These parameters balance preservation of local and global structure in the low-dimensional embedding.

Cell Clustering and Community Detection

Neighborhood Graph Construction

Cell similarity graphs are constructed using the scanpy.pp.neighbors function, which builds a k-nearest neighbor (kNN) graph in PCA space. The default configuration uses 15 nearest neighbors with Euclidean distance metrics. The resulting adjacency matrix is refined using Jaccard similarity to weight edges based on shared neighborhood overlap, improving cluster quality and stability.

The neighborhood graph serves as input for both clustering algorithms and UMAP embedding, ensuring consistency between clustering results and visualization coordinates.

Leiden Clustering Algorithm

Unsupervised cell clustering employs the Leiden algorithm, which optimizes the Constant Potts Model modularity function to identify community structure in the cell neighborhood graph. The Leiden algorithm was selected over the related Louvain algorithm due to its improved guarantee of well-connected communities and better worst-case time complexity.

Default clustering resolution is set to 0.8, empirically determined to provide balanced cluster sizes for typical single-cell datasets. Users can adjust resolution parameters to obtain finer (higher resolution) or coarser (lower resolution) clustering granularity based on biological expectations and dataset characteristics.

Optimal Resolution Selection

For automated resolution selection, CellPilot implements the autoResolution function from OmicVerse, which evaluates clustering quality across multiple resolution parameters. The algorithm computes silhouette scores, modularity metrics, and cluster stability measures to identify the resolution providing optimal trade-offs between cluster separation and biological interpretability.

The selection process evaluates resolutions from 0.1 to 2.0 in increments of 0.1, computing quality metrics for each configuration. The optimal resolution is selected based on composite scoring that weights silhouette coefficient (40%), modularity (30%), and cluster number penalty (30%) to avoid over-clustering artifacts.

Marker Gene Identification and Characterization

Differential Expression Analysis

Cluster-specific marker genes are identified using the Wilcoxon rank-sum test, implemented through scanpy.tl.rank_genes_groups. This non-parametric test is well-suited for single-cell expression data, which often violates normality assumptions required for parametric tests. The test compares gene expression in each cluster against all other cells, identifying genes with significantly elevated expression in specific cell populations.

Statistical significance is assessed using Benjamini-Hochberg correction for multiple testing, with adjusted p-values <0.05 considered significant. Additional filtering criteria include minimum log-fold change (default ≥0.25) and minimum fraction of cells expressing the gene within the cluster (default ≥25%).

Alternative differential expression methods are available for specialized analyses, including the t-test for parametric comparisons and the logistic regression approach for handling covariates and batch effects.

Gene Set Enrichment and Functional Annotation

Identified marker genes undergo functional enrichment analysis using gene ontology (GO) terms, KEGG pathways, and Reactome pathway databases. Enrichment analysis utilizes the hypergeometric test implemented through the GSEApy library, with multiple testing correction applied to control false discovery rates.

Pathway analysis results are integrated into the user interface, providing contextual information about cluster identities and potential functional roles of identified cell populations. Interactive pathway visualizations enable exploration of gene-pathway relationships and facilitate biological interpretation of clustering results.

Cell Type Annotation Framework

Reference Database Integration

CellPilot integrates multiple curated reference databases for automated cell type annotation, providing comprehensive coverage across tissue types and species. The primary databases include:

CellMarker Database: Contains manually curated cell markers for 467 cell types in 158 human tissues and 389 cell types in 81 mouse tissues. The database includes both positive and negative markers with evidence codes and literature references. Data are accessed through local database files to ensure consistent performance and avoid network dependencies.

PanglaoDB: Provides cell type markers derived from single-cell sequencing experiments across multiple species and tissues. The database includes 8,230 cell type markers for human and mouse, with statistical validation and cluster-specific expression evidence. Integration utilizes the OmicVerse implementation with local database caching.

Cancer Single Cell Atlas (CancerSEA): Focuses specifically on cancer cell types and states, including 25 functional states across 125 cancer types. This specialized database enhances annotation accuracy for oncological applications and tumor microenvironment characterization.

Automated Annotation Algorithm

The annotation algorithm implements a score-based approach comparing cluster marker genes against reference database entries. For each potential cell type in the reference databases, the algorithm calculates enrichment scores based on the overlap between cluster markers and known cell type markers.

Scoring utilizes the hypergeometric test to assess statistical significance of marker gene overlap, with additional weighting based on marker gene strength (log-fold change) and specificity (fraction of expressing cells). The final annotation score combines statistical significance with biological relevance metrics:

Score = -log10(p_value) × median_logFC × marker_specificity

where p_value represents hypergeometric test significance, median_logFC represents the median log-fold change of overlapping markers, and marker_specificity represents the average specificity of markers in the cluster.

Cell type assignments are made based on the highest-scoring annotation for each cluster, with confidence scores provided to indicate annotation reliability. Clusters with low confidence scores (<0.5) are flagged for manual review and potential reannotation.

Manual Annotation with Custom Marker Genes

Custom Marker Gene Upload System

CellPilot incorporates a novel manual annotation feature enabling researchers to leverage domain-specific knowledge through custom marker gene definitions. The system accepts marker gene files in multiple formats (CSV, TSV, TXT) with flexible column naming conventions to accommodate diverse user preferences.

The file parsing system automatically detects column separators and handles common variations in column headers (cell_type/celltype/cell type, gene/gene_symbol/symbol). Data validation includes gene symbol verification against the dataset's feature names, with fuzzy matching to handle minor nomenclature differences and automatic case conversion.

Integration with Automated Annotation

Custom marker genes are processed through the same statistical framework as reference databases, ensuring consistent scoring and annotation quality. The manual annotation module calculates expression scores for custom markers across all cells, generating cluster-specific enrichment profiles.

When both automated and manual annotations are enabled, the system provides comparative results allowing users to evaluate consistency between reference database predictions and manual annotations. Conflicting annotations are highlighted in the results interface, facilitating expert review and final cell type assignment decisions.

The manual annotation system supports hierarchical cell type definitions, enabling users to define both broad cell categories (e.g., "T cell") and specific subtypes (e.g., "CD8+ effector T cell") within the same marker file. The algorithm respects these hierarchical relationships during scoring and annotation assignment.

Advanced Clustering Validation and Quality Assessment

Cluster Stability Analysis

CellPilot implements cluster stability assessment through bootstrap resampling and consensus clustering approaches. The stability analysis evaluates clustering robustness by repeatedly clustering subsampled datasets and measuring cluster assignment consistency across iterations.

For each bootstrap iteration, 80% of cells are randomly sampled without replacement, clustered using identical parameters, and compared against the full dataset clustering. Stability scores are calculated using the Adjusted Rand Index (ARI) to measure clustering similarity, with stable clusters achieving ARI scores >0.7 across bootstrap iterations.

Silhouette Analysis

Clustering quality is further assessed using silhouette analysis, which measures how similar cells are to their assigned cluster compared to neighboring clusters. Silhouette scores range from -1 to +1, with positive scores indicating well-separated clusters and negative scores suggesting potential misassignment.

The analysis generates cluster-level silhouette scores and identifies individual cells with negative silhouette values for potential reclassification. Interactive visualizations display silhouette profiles across clusters, enabling users to assess clustering quality and identify problematic cluster assignments.

Cell-Cell Communication Analysis

CellPhoneDB Statistical Framework

Intercellular communication analysis utilizes CellPhoneDB 5.0.1, implementing a statistical framework for predicting ligand-receptor interactions between cell types. The method quantifies communication potential based on co-expression of receptor-ligand pairs across different cell populations.

The statistical significance assessment employs permutation testing with 1000 iterations by default (user-adjustable). During each permutation, cell type labels are randomly shuffled while preserving cell type proportions, generating a null distribution of interaction scores. Observed interaction scores are compared against this null distribution to calculate empirical p-values.

Significant interactions are defined as those with p-values <0.05 after multiple testing correction using the Benjamini-Hochberg method. Additional filtering criteria include minimum expression thresholds (default: expressed in ≥10% of cells) and minimum interaction score thresholds to focus on biologically relevant communications.

Interaction Network Construction

Cell-cell communication networks are constructed based on significant ligand-receptor interactions, with nodes representing cell types and edges representing communication pathways. Edge weights correspond to interaction significance (-log10 p-value) and interaction strength (mean expression product).

Network analysis includes calculation of centrality measures (degree, betweenness, closeness) to identify highly connected cell types and key communication hubs within the cellular ecosystem. These metrics provide insights into which cell types serve as major communication coordinators and which represent more specialized or isolated populations.

Visualization and Interpretation Tools

CellPhoneDB results are visualized through multiple complementary approaches:

Interaction Heatmaps: Display interaction strength matrices between all cell type pairs, with hierarchical clustering to identify communication modules and patterns.

Chord Diagrams: Circular network representations highlighting the directionality and strength of communications between cell types.

Network Graphs: Force-directed layouts showing cell types as nodes with interaction edges, sized and colored by communication strength.

Detailed Dot Plots: Gene-level visualizations showing ligand and receptor expression levels for specific interactions of interest.

Copy Number Variation Analysis and Tumor Cell Detection

inferCNVpy Implementation

Chromosomal copy number variation analysis employs inferCNVpy 0.4.5, providing Python integration for the established inferCNV methodology. The algorithm infers CNV profiles by analyzing gene expression patterns across chromosomal positions, leveraging the correlation between gene dosage and expression levels.

Reference cell selection utilizes immune and stromal cell populations identified through cell type annotation, as these cells are typically diploid and provide stable reference baselines. The algorithm requires a minimum of 50 reference cells per reference group to ensure statistical robustness.

Sliding Window Analysis

CNV detection utilizes a sliding window approach with default window size of 250 genes, empirically optimized for single-cell expression noise characteristics. Gene coordinates are obtained from GENCODE v47 annotation files, ensuring compatibility with current genomic reference standards.

The sliding window calculation generates smoothed expression profiles across each chromosome, reducing technical noise while preserving large-scale copy number alterations. Window overlap of 50% provides smooth CNV profiles while maintaining sensitivity to focal alterations.

CNV Score Calculation and Classification

CNV scores are calculated for each cell using a modified z-score approach, comparing observed expression patterns against reference cell populations. The scoring algorithm accounts for chromosome-specific expression variability and applies normalization to ensure comparable scores across different chromosomal regions.

Tumor cell classification utilizes adaptive thresholding based on the distribution of CNV scores within the dataset. The default threshold (CNV score >0.1) can be adjusted based on dataset characteristics and expected tumor content. Cells exceeding the threshold are classified as potential tumor cells for subsequent analysis.

Validation and Quality Control

CNV analysis includes multiple quality control steps to ensure reliable tumor cell identification:

Reference Cell Quality: Assessment of reference cell populations for genomic stability and minimal CNV signal.

Chromosome Coverage: Verification of adequate gene coverage across all chromosomes for comprehensive CNV detection.

Signal-to-Noise Ratio: Evaluation of CNV signal strength relative to technical noise levels.

Correlation Analysis: Assessment of CNV profile correlation between nearby cells and clustering consistency.

Drug Response Prediction Framework

CaDRReS-Sc Integration

Drug sensitivity prediction integrates the CaDRReS-Sc (Cancer Drug Response Prediction for Single-Cell) framework, enabling prediction of therapeutic responses at single-cell resolution. The system utilizes pre-trained models built on Genomics of Drug Sensitivity in Cancer (GDSC) data, covering 192 FDA-approved and experimental compounds across multiple cancer types.

The CaDRReS-Sc implementation includes two complementary models: (1) a bulk expression model trained on cancer cell line drug sensitivity data, and (2) a single-cell model accounting for intratumoral heterogeneity and cell state-specific responses. Model selection is automatically determined based on dataset characteristics and user preferences.

GDSC Database Integration

Drug response predictions utilize the GDSC database, containing IC50 measurements for cancer cell lines across a comprehensive panel of therapeutic compounds. The database integration includes automatic downloading and caching of required data files, ensuring consistent model performance while minimizing network dependencies.

Compound annotations include mechanism of action, target pathways, clinical trial status, and FDA approval information. This metadata enables interpretation of predicted responses in therapeutic contexts and identification of actionable drug targets.

Prediction Algorithm and Model Architecture

The CaDRReS-Sc models employ ensemble approaches combining multiple machine learning algorithms:

Random Forest Regressors: Provide robust predictions with feature importance rankings for drug sensitivity drivers.

Gradient Boosting Machines: Capture non-linear relationships between gene expression patterns and drug responses.

Neural Network Models: Deep learning architectures trained on high-dimensional expression profiles.

Elastic Net Regression: Linear models with regularization for interpretable coefficient estimation.

Ensemble predictions combine individual model outputs using weighted averaging, with weights determined through cross-validation performance on GDSC training data.

Single-Cell Drug Response Analysis

For tumor cells identified through CNV analysis, drug response predictions are generated for individual cells and aggregated at the cluster level. Single-cell predictions account for expression heterogeneity within tumor populations, identifying subpopulations with differential drug sensitivities.

Cluster-level analysis includes:

Mean IC50 Predictions: Average predicted drug sensitivity across cells within each tumor cluster.

Response Heterogeneity: Variance in predicted responses within clusters, indicating potential resistance mechanisms.

Sensitive Cell Fractions: Proportion of cells predicted to respond to each compound, enabling assessment of therapeutic coverage.

Drug Ranking: Prioritization of compounds based on predicted efficacy and tumor coverage metrics.

Visualization and Interpretation

Drug response results are presented through multiple visualization modalities:

Response Distribution Plots: Histograms and violin plots displaying prediction distributions for compounds of interest.

Statistical Methods and Validation

Differential Expression Testing

Statistical testing for marker gene identification employs the Wilcoxon rank-sum test (Mann-Whitney U test), selected for its robustness to non-normal distributions characteristic of single-cell expression data. The test compares gene expression between each cluster and all remaining cells, generating effect sizes (log-fold changes) and statistical significance measures.

Multiple testing correction utilizes the Benjamini-Hochberg procedure to control false discovery rate (FDR) at α = 0.05. Additional filtering criteria include minimum expression thresholds and effect size requirements to ensure biological relevance of identified markers.

Cell-Cell Communication Statistics

CellPhoneDB statistical analysis employs permutation testing to assess interaction significance while preserving dataset structure. The null hypothesis assumes no specific interactions between cell types, tested through random permutation of cell type labels while maintaining cell type proportions.

Permutation-based p-values are calculated as: p = (number of permutations with score ≥ observed score) / total permutations. Multiple testing correction accounts for the large number of tested interactions using the Benjamini-Hochberg method.

CNV Analysis Validation

Copy number variation detection employs statistical approaches adapted for single-cell data characteristics:

Z-score Normalization: CNV scores calculated relative to reference cell populations using standard z-score transformation.

Chromosome-Specific Normalization: Adjustment for chromosome-specific expression patterns and technical biases.

Sliding Window Statistics: Robust averaging within genomic windows to reduce noise while preserving signal.

Threshold Selection: Adaptive thresholding based on dataset-specific CNV score distributions and expected tumor content.
